# SarcDBase

SarcDBase (the Sarcoma Data Base) is a tool that integrates high-throughput sequencing data from tumor samples with relevant genetic and clinical information.

SarcDBase facilitates the filtering of annotated mutational data for whole-genome and transcriptome sequencing against lists of clinically relevant mutations (for instance: genes mentioned in the WHO Classification of tumours). Users may define their own lists of interesting genes/fusions to simplify sifting through new data.


## Getting Started

SarcDBase is implemented in python. Before you can run this repository, make sure you have installed and set up:

- Git. `https://github.com/git-guides/install-git`
- Conda. `Install it through miniconda or anaconda`
- Python

### Installation

Clone the SarcDBase repository and execute the following commands to generate a conda environment with all you need to run the tool:

```
git clone https://github.com//ValeriaDifilippo/SarcDBase
cd SarcDBase
conda env create -f bin/config/environment.yml
conda activate SarcDBase
```

Then manually install cyvcf2 within the envirnoment:

```
pip install cyvcf2
```
Alternatively, you can manually download the latest release, extract and then perfrom the above steps.

Next, create a results directory within the SarcDBase directory: 
```
mkdir results
```

**Project folder structure**

The project is organized into the following main directories:

- _bin/_
This directory contains all the source codes and scripts used to run SarcDBase. In the _config/_ subdirectory you can find the configuration file to set up your environment.

- _annotation_files/_
Contains the annotation files in `.txt` format for the analysis, such as WHO_annotation_list_(hg19 or hg38).txt. In this folder, you can place your own annotation file(s).

- _results/_
This directory will contain subdirectories for each analysed case with results generated by running SarcDBase. Fell free to create project-specific directories within /results .

## Usage
**Running SarcDBase**

***Set up***

This step creates a subfolder in the results/ directory for each case, named as per the cohort.txt list.
Create a tab delimtied cohort.txt file according to the following format:

Example of the cohort.txt

| Sample | Sex | Age | Location |
| --- | --- | --- | --- |
| Case1 | Woman | 20 | Bone |
| Case2 | Woman | 14 | Soft tissue |		

Then run to create a folder and a *_case_information.txt file for each case in the list:
```
python set_up.py -file cohort.txt -output results
```
or:
```
python set_up.py -file cohort.txt -output results -filter Case1 Case3 
```
The default for -filter is ALL, meaning that all the cases reported in the list are analyzed, otherwise you can specify the certain cases. A folder and a *_case_information.txt will be created only for those.

*** IMPORTANT TO KEEP IN MIND FOR NEXT STEPS!! ***
- All vcf files (snv/indels, sv, etc...)  that are to be analyzed need to be uniformly named starting with the case number as present in the cohort list (for instance: Case1_sv.vcf, Case1_snv.vcf, Case1_cn.vcf, Case1_fusions.txt)!
- All SarcDBase output files created for each case will be to be saved in the folder relative for that case.

***Structural variants (SVs) module***

This step takes vcf files from a structural variant caller and then annotates and matches with the provided annoation list. If not interested in structural variants, skip this step.

```
python3 path/to/SarcDBase/bin/sv.py -file path/to/${sample}.vcf -annotation path/to/SarcDBase/annotation_files/WHO_annotation_list.txt -outfile path/to/SarcDBase/results/${sample}*_sv.txt -filter PASS
```
The script below utilizes a for loop to provide correct sample names, modify as needed.

```
for file in /path/to/*sv.vcf; do sample=$(basename "$file" | sed 's/_sv.vcf$//'); echo "running vcf file $sample"; python /path/to/SarcDBase-1.0.0/bin/sv.py -file $file -annotation /path/to/SarcDBase-1.0.0/annotation_files/WHO_annotation_list_hg38.txt -outfile /path/to/SarcDBase-1.0.0/results/$sample/${sample}_sv.txt -filter PASS; done
```

***Single nucleotides variants and Indels (SNVs and Indel) module***

This step takes vcf files from a single nucleotide and indel variant caller and then annotates and matches with the provided annoation list. If not interested in SNV and INDEL variants, skip this step.

```
python3 path/to/SarcDBase/bin/point_mutations.py -file path/to/${sample}.vcf -annotation path/to/SarcDBase/annotation_files/WHO_annotation_list.txt -outfile path/to/SarcDBase/results/${sample}*_snv.txt -filter PASS
```
The script below utilizes a for loop to provide correct sample names, modify as needed.

```
for file in /path/to/*_snv.vcf; do sample=$(basename "$file" | sed 's/_snv.vcf$//'); echo "running vcf file $sample"; python /path/to/SarcDBase-1.0.0/bin/point_mutations.py -file $file -annotation /path/to/SarcDBase-1.0.0/annotation_files/WHO_annotation_list_hg38.txt -outfile /path/to/SarcDBase-1.0.0/results/$sample/${sample}_snv.txt -filter PASS; done
```

***Copy number variations (CNVs) module***

This step creates one copy number variantion plot of all chromosomes (1-22, X and Y) in .jpeg format and a .txt file that can be used to dynamically visualize the copy number profile in the SarcDBase app. As input, it uses tab-delimited files in .txt format containing only the columns as exemplified below. It is recommended to export these specific columns from the output of the copy number caller that you are using and save as Case1_cn.txt 

Example cn.txt file format that is handled by the script - chromosomes should be given as 1, 2, 3 and NOT chr1, chr2, chr3:

| chromosome | start | gene | log2 |
| --- | --- | --- | --- |
| 1 | 730001 | - | 0.0246395335604405 |
| 1 | 2160001 | SKI | 0.0194795127269489 |			 
			

```
python3 path/to/SarcDBase/bin/copy_number.py -file path/to/${sample}.txt -annotation path/to/SarcDBase/annotation_files/WHO_annotation_list.txt -outfile path/to/SarcDBase/results/$sample/${sample}_cn.jpeg
```
The script below utilizes a for loop to provide correct sample names, modify as needed.

```
for file in /path/to/*cn.txt; do sample=$(basename "$file" | sed 's/_cn.txt$//'); echo "generating copy number plot for $sample"; python /path/to/SarcDBase-1.0.0/bin/copy_number.py -file $file -annotation /path/to/SarcDBase-1.0.0/annotation_files/WHO_annotation_list_hg38.txt -outfile /path/to/SarcDBase-1.0.0/results/$sample/${sample}_cn.jpeg; done
```

***Fusion genes module***

This step matches the output of a fusion gene caller all reported gene fusions in the latest release of the Mitelman database (https://mitelmandatabase.isb-cgc.org/)

Example fusions.txt file format that is handled by the script - you need to extract gene fusions from your caller of choice and provide them in this format with one column only:

| GeneFusion |
| --- |
| EWSR1::FLI1 | 
| FUS::DDIT3 | 


```
python3 path/to/SarcDBase/bin/funsion.py -file path/to/${sample}.txt -annotation path/to/SarcDBase/annotation_files/mitelman_databse.txt -o path/to/SarcDBase/results/$sample/${sample}_fusion.txt
```
The script below utilizes a for loop to provide correct sample names, modify as needed.

```
for file in /path/to/*fusions.txt; do sample=$(basename "$file" | sed 's/_fusions.txt$//'); echo "matching fusions for $sample"; python /path/to/SarcDBase-1.0.0/bin/funsion.py -file $file -annotation /path/to/SarcDBase-1.0.0/annotation_files/mitelman_databse.txt -o /path/to/SarcDBase-1.0.0/results/$sample/${sample}_fusion.txt; done
```

***Report module***

If you wish you can create an html report containing all the information generated for a spefic case, run the following:

```
python3 path/to/SarcDBase/bin/report.py -file path/to/sample/ -o path/to/SarcDBase/results/sample/sample_report.html
```
The script below utilizes a for loop to provide correct sample names, modify as needed.

```
for case in /path/to/SarcDBase-1.0.0/results/*; do sample=$(echo $case | cut -d "/" -f4); echo "generating report for $sample"; python /path/to/SarcDBase-1.0.0/bin/report.py -file $case/ -o /path/to/SarcDBase-1.0.0/results/$sample/${sample}_report.html; done
```
